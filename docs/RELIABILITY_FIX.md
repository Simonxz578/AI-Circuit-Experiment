# 识别中断与多开关图片修复

2026-10-30。用户反馈上传含两个开关的电路图时，出现“AI服务连接中断”或无法识别的提示。

## 已定位的问题

- 原后端在模型正文为空时直接抛出普通异常，随后统一显示成连接中断；没有检查 `finish_reason`，无法区分空白正文、输出长度截断、模型资源中断和真实网络错误。
- 原识别请求同时要求长篇证据、严格图形坐标和物理核查，使用高推理强度；图中未知数值和多种开关状态容易引发不必要的解题。原服务端60秒、网页65秒上限与图片任务的实际耗时接近，且等待期间没有流式保活。
- 本可规范化的表示差异（例如R₁、数值带Ω、可选元件名称/证据、非标准画布坐标）会被整个拒绝，而不是仅核验实际元件与连接。
- 页首“AI服务已连接”实际仅检测到后端配置，不代表供应商正在正常返回结果，容易误导。

这次未取得用户报错请求的历史 `finish_reason`，因此不把某一供应商故障推断为该次请求的唯一原因。已通过代码回归复现并修复错误归类，并用同类原创双开关图与缺值图进行真实API测试。

## 修改

- 单独提取实际拓扑，不让模型求解题目答案。缺值、开关断开、多个开关都可正常生成实验草图。
- 简化响应为必需的节点/端子/参数，采用低强度推理；本地规范化别名、下标、显式单位和画布坐标。规范化不新增任何猜测导线或数值；节点引用错误仍需重新核验。
- 显式检查空正文、空白正文、`length`、`aborted`、`insufficient_system_resource`、无效JSON和无效节点。最多自动恢复一次；每次恢复均消耗真实服务端限额，不无限重试。
- 流式阶段状态与每8秒心跳保持连接；不传出模型推理。页面显示真实等待秒数，取消会中止后端任务。总任务预算约120秒，网页135秒上限。
- 分开显示超时、空输出、被截断、服务忙、余额/授权、网页连接故障和接线核验错误；保留图片/当前电路并提供“重试识别”。
- 页首改为“AI服务已配置”。日志仅记录问题编号、结束原因、用量和耗时，不记录图片、题干、密钥或模型推理。

## 验证

- 单元/集成：66 / 66 通过，包含空白/截断/资源中断的有限恢复、每次恢复计费计数、连接规范化、超过65秒的请求、流式断流、取消传播和双开关全部四种状态。
- 桌面/手机：24 / 24 通过，包含上传保留、流式失败后重试、参数、曲线、缺值及确认流程。
- 已部署Worker原五类真实API回归：5 / 5 通过，串联1A、并联6A、混联3A、文字1A、AI新增串联电阻0.625A；耗时约9.25/3.04/4.13/3.01/1.99秒。
- 同类双开关图：旧请求约47.27秒；修复后初次约9.85秒；仅给R1+R2=30Ω、未给各元件值的双开关图约13.36秒，成功生成未知参数草图。
- 供复现的两张电路图片是本项目原创，不是用户原题截图。供应商输出、结束状态和计数证据位于 `docs/evidence/reliability/`，未保留供应商推理正文。
